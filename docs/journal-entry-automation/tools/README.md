# 評価スクリプト evaluate.py

[← 03 データと評価の設計](../03-data-and-eval.md) ｜ [04 PoC](../04-poc.md)

正解CSVとAI出力CSVを突き合わせて、[03章](../03-data-and-eval.md#5-評価指標を決める)で定義した指標を出します。Python 3 の標準ライブラリだけで動きます。

## 動かしてみる

```bash
cd docs/journal-entry-automation/tools
python3 evaluate.py --truth sample/ground_truth.csv --pred sample/predictions.csv --errors errors.csv
```

`errors.csv` には誤った行だけが書き出されます。「原因の部品」「誤りパターン」「対策の案」の列を埋めれば、そのまま[エラー分析シート](../templates/error-analysis.csv)になります。

## サンプルデータに仕込んである誤り

出力の読み方の練習用に、サンプルデータには次の誤りを入れてあります。出力のどこに出るか確認してください。

| 証憑 | 仕込んだ誤り | 出力のどこに出るか |
|---|---|---|
| INV-0004 行1 | 「事務用品費」と出力（正解は消耗品費だが、許容リストに含まれる） | **誤りにならない**（acceptable_accounts の効果） |
| INV-0004 行2 | 10万円以上の備品を正しく「要確認」にした | カバレッジが下がるが誤りではない |
| INV-0004 行4 | 部門の取り違え（管理部 → 営業部） | 軽微、部門の取り違え |
| INV-0005 行3 | 修繕費を消耗品費と誤る | 重大、勘定科目の取り違え |
| INV-0005 行4 | **明細の取り漏れ**（AIが出力していない） | 致命的、取り漏れ1行 |
| INV-0008 行1 | 源泉ありの支払いを要確認にした（補助科目は空） | 軽微、要確認に回せていた |
| INV-0012 行3 | 飲料の税区分を10%と誤る（正解は8%軽減） | 致命的、税区分の取り違え |
| INV-0012 行5 | 存在しない行を出力 | 余計な行 |

## 出力の読み方

| 出力 | 意味 | 見るポイント |
|---|---|---|
| 明細の取り漏れ | 正解にあるのにAIが出力しなかった行 | 0でなければ最優先で原因調査。人が気付けない |
| 項目別正解率 | 項目ごとの当たり率（要確認の行も含む） | どの項目が弱いか |
| 行の完全一致率 ±○pt | 全項目が合っている行の割合と、95%信頼区間の半幅 | ±が大きいときは件数が足りない |
| 証憑単位の完全一致率 | 請求書1枚の全行が合っている割合 | 業務効果に一番近い |
| カバレッジ | 要確認にしなかった行の割合（取り漏れは「回答した」扱い） | 人に回す量 |
| 回答した行の完全一致率 | AIが自信を持って出した行の正解率 | 合格基準と比べる |
| 回答した行の致命的誤り率 | AIが要確認にせず、税区分・金額を誤った（または取り漏れた）割合 | **最重要**。ここが高いと使えない |
| 証憑まるごと自動で正解の割合 | 1枚の全行が「要確認なし・正解」の割合 | 人が一覧で承認するだけで済む割合 |
| 型別の表 | 型ごとの結果 | 30行未満の型は誤差が大きいので参考値 |
| 誤りの重さ別 | 致命的・重大・軽微の件数と、要確認に回せていた件数 | 致命的なものが要確認に回せているか |
| よくある取り違え | 正解 → AI出力 のペアの上位 | エラー分析の入口 |
| 余計な行 | 正解にない行をAIが出力 | 金額の二重計上につながるので要注意（指標には含まれないので別途確認） |

## 誤りの重さの定義を変えたいとき

`evaluate.py` 冒頭の `CRITICAL_FIELDS`（致命的）と `MAJOR_FIELDS`（重大）を、顧客と合意した定義に合わせて変更してください。

# 評価スクリプト evaluate.py

[← 03 データと評価の設計](../03-data-and-eval.md) ｜ [04 PoC](../04-poc.md)

正解CSVとAI出力CSVを突き合わせて、[03章](../03-data-and-eval.md#6-カバレッジと正解率はトレードオフ)で定義した指標を出します。
**抽出・分類タスク** なら業務を問わず使えます。業務ごとの違いは設定ファイル（JSON）で指定します。Python 3 の標準ライブラリだけで動きます。

> 要約・生成タスク（回答メール案など）は正解が1つではないので、このスクリプトではなくルーブリック採点を使います（→ [03](../03-data-and-eval.md#5-タスクの型ごとの評価方法)）。

## 動かしてみる

```bash
cd docs/ai-business-integration/tools

# 例1：仕訳入力（請求書の明細ごとの仕訳）
python3 evaluate.py --config sample/journal/config.json \
  --truth sample/journal/ground_truth.csv --pred sample/journal/predictions.csv --errors errors.csv

# 例2：問い合わせメールの分類と振り分け
python3 evaluate.py --config sample/inquiry/config.json \
  --truth sample/inquiry/ground_truth.csv --pred sample/inquiry/predictions.csv
```

`--errors` を付けると、誤った行だけがCSVに書き出されます。「原因の部品」「誤りパターン」「対策の案」の列を埋めれば、そのまま[エラー分析シート](../templates/error-analysis.csv)になります。

## 自分の業務で使うには

1. 正解CSVとAI出力CSVを用意する（1行 = 1つの判定単位。両方に同じID列を入れる）
2. 設定ファイルを作る

```json
{
  "name": "業務の名前",
  "keys": ["id"],                  // 1行を特定する列。複数可（例：["doc_id", "line_no"]）
  "group_by": "doc_id",            // 書類などのまとまり単位で集計したいとき（省略可）
  "segment": "segment",            // 型別に集計する列（正解CSV側、省略可）
  "review_column": "needs_review", // AIが要確認にしたかの列（AI出力側、省略可）
  "missing_severity": "致命的",     // AIが出力しなかった行の重さ
  "fields": {                      // 採点する項目と、誤ったときの重さ
    "category": {"label": "種類", "severity": "重大"},
    "amount":   {"label": "金額", "severity": "致命的", "type": "number"}
  }
}
```
（実際のJSONにはコメント `//` は書けません。[sample/journal/config.json](./sample/journal/config.json) を参考にしてください）

3. どちらでも正解とする値がある場合は、正解CSVに `acceptable_<項目名>` 列を作り、`;` 区切りで書く
4. 誤りの重さ（`severity`）は、顧客と合意した定義（→ [03 誤りの重さ](../03-data-and-eval.md#3-3-誤りの重さを決める)）に合わせる

## サンプルに仕込んである誤り（出力の読み方の練習用）

### 仕訳入力（sample/journal）

| データ | 仕込んだ誤り | 出力のどこに出るか |
|---|---|---|
| INV-0004 行1 | 「事務用品費」と出力（許容リストに含まれる） | **誤りにならない** |
| INV-0004 行2 | 10万円以上の備品を正しく「要確認」にした | カバレッジが下がるが誤りではない |
| INV-0004 行4 | 部門の取り違え | 軽微 |
| INV-0005 行3 | 修繕費を消耗品費と誤る | 重大 |
| INV-0005 行4 | **AIが出力していない（取り漏れ）** | 致命的、取り漏れ1行 |
| INV-0008 行1 | 要確認にした（補助科目は空） | 軽微、要確認に回せていた |
| INV-0012 行3 | 税区分の誤り | 致命的 |
| INV-0012 行5 | 存在しない行を出力 | 余計な行 |

### 問い合わせ分類（sample/inquiry）

| データ | 仕込んだ誤り | 出力のどこに出るか |
|---|---|---|
| Q-005 | 解約を「契約内容の変更」・緊急度中と誤る | 致命的（緊急度の誤り） |
| Q-006 | 「要望」と出力（許容リストに含まれる） | **誤りにならない** |
| Q-007 | 担当チームの誤り | 軽微 |
| Q-008 | 障害報告を誤分類したが、要確認にした | 致命的だが要確認に回せていた |
| Q-011 | **AIが出力していない** | 致命的、取り漏れ |

## 出力の読み方

| 出力 | 意味 | 見るポイント |
|---|---|---|
| 取り漏れ | 正解にあるのにAIが出力しなかった行 | 0でなければ最優先で原因調査。人が気付けない |
| 項目別正解率 | 項目ごとの当たり率（要確認の行も含む） | どの項目が弱いか |
| 完全一致率 ±○pt | 全項目が合っている行の割合と、95%信頼区間の半幅 | ±が大きいときは件数が足りない |
| まとまり単位の完全一致率 | 書類1件の全行が合っている割合 | 業務効果に近い |
| カバレッジ | 要確認にしなかった行の割合（取り漏れは「回答した」扱い） | 人に回す量 |
| 回答した行の完全一致率 | AIが自信を持って出した行の正解率 | 合格基準と比べる |
| 回答した行の致命的誤り率 | AIが要確認にせず、致命的な誤りをした割合 | **最重要** |
| 型別の表 | 型ごとの結果 | 30行未満の型は誤差が大きいので参考値 |
| 誤りの重さ別 | 致命的・重大・軽微の件数と、要確認に回せていた件数 | 致命的なものが要確認に回せているか |
| よくある取り違え | 正解 → AI出力 のペアの上位 | エラー分析の入口 |
| 余計な行 | 正解にない行をAIが出力 | 二重計上・誤送信につながりうる（指標には含まれないので別途確認） |

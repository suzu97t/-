# AIを業務で機能させるために整えること

AI を業務に適用する担当者（若手）とお客様に向けた説明資料。表紙＋本文10ページ。
「AI を導入すれば仕事の大半は解決する」という見方に対して、AI が業務で機能するまでに越える壁（インプットの完全性・AIリーダビリティ・アウトプット設計・説明責任）を、調査の数字・判例・業務場面の例で説明する。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `deck.html` | 正本（16:9、1 section = 1スライド）。直すときはこれを直す |
| `deck.pdf` | 配布用。`deck.html` を Chromium で印刷したもの |
| `deck.pptx` | 編集用。`deck.html` から変換したもの（グラフ以外は文字・表を編集できる） |
| `sources.md` | 載せた数字・事例の出典と、照合の程度 |
| `qa.md` | 機械チェックの経過と、ページごとの目視確認の記録。社外に出す前に残る確認 |
| `review.md` | 文脈を伏せた別のレビュアーの指摘と、その採否表 |

## ストーリー（ページのタイトル）

| ページ | タイトル |
| --- | --- |
| P.1 | エグゼクティブサマリー |
| P.2 | AIを全社に広げる企業は増えたが、利益への貢献を答える企業の割合は増えていない |
| P.3 | AIの取り組みが止まる理由は、性能よりもデータの質・価値の定義・リスク管理にある |
| P.4 | AIが成果を出すには、情報を集めてから成果物を渡すまでの各段で人の側の準備が要る |
| P.5 | ① AIは渡された情報でしか答えないため、最新版・口頭の決定・暗黙知を記録に残す |
| P.6 | ② 人が見やすく整えた資料ほどAIは読み違えるため、形式の変換と構造化を先に行う |
| P.7 | ③ 成果物の粒度・形式・合格基準と渡し先を先に決めると、出力をそのまま業務に流せる |
| P.8 | ④ AIの誤りの責任は使った側が負うため、根拠を示させ、人が確かめる手順を組み込む |
| P.9 | 着手前に業務部門と壁ごとの問いに答え、答えられない壁の整備を計画に入れる |
| P.10 | 業務を1つ選び、出力と合格基準を決めてから小さく試し、記録をもとに直し続ける |

## 作り方と再検査

[carnot-tech/jinba-consulting-pptx-skill](https://github.com/carnot-tech/jinba-consulting-pptx-skill)（コミット 5e781b4）の部品（`new_deck.py`）と規約で組み、同スキルの検査を通した。

```bash
# スキルを別の場所に clone してから（このリポジトリには含めていない）
python3 scripts/check_all.py <このフォルダ>/deck.html --sources <このフォルダ>/sources.md   # 0 FAIL / 0 WARN
python3 scripts/snapshot.py <このフォルダ>/deck.html      # PDF と確認用の画像
python3 scripts/html_to_pptx.py <このフォルダ>/deck.html  # PPTX
```
